# ADR-0008：未来 CAD 集成优先 Onshape

- 状态：已采纳的产品方向；集成尚未实现。
- 原始记录：PDR-1，2026-09-14，见 [AGENTS.md](../../AGENTS.md)。
- ADR 回溯记录日期：2026-10-13。
- 文档基线：Ansatz `0.4.0`，提交 `51d18d4`。

## 背景

未来的装配导入导出、宿主 CAD 联动或远程建模，需要选择首个集成目标。
已有 PDR-1 将 Onshape 列为优先候选，同时要求在开始实施前重新核验平台
接口和约束语义。该产品方向早于本 ADR，本记录不代表已经实现或验证适配。

原始平台调研事实与来源继续保留在 AGENTS.md；本 ADR 只记录其对 Ansatz
架构和实施顺序的约束，不将历史调研表述为当前接口兼容性保证。

## 决策

1. 开始建设 CAD 集成层时，优先评估 Onshape，按 PDR-1 重新核验所需接口。
2. 适配层负责实体、局部参考几何、约束和诊断的映射。网络、认证和宿主
   文档生命周期位于产品数值核心之外。
3. Onshape 的 mate/feature 语义是适配对象；Ansatz 的模型语义由自己的
   类型、Schema、ADR 和独立几何校验定义。
4. 不支持或有损的映射应明确报告，不能静默近似后宣称约束已满足。
5. 内核可信度、真实模型验证和接口版本策略先于完整集成交付。

## 考虑过的替代方案

| 方案 | 取舍 |
|---|---|
| 同时接入多种 CAD | 扩大映射与维护面，不利于验证首条完整链路 |
| 先绑定某一宿主的 solver 或网络 API 到核心 | 会削弱纯核心、可嵌入和独立语义，增加宿主依赖 |
| 长期只做独立求解、没有适配 | 便于聚焦内核，但无法验证实际建模流程和真实集成需求 |

Onshape 优先是实施顺序的选择，不意味着已经决定所有后续平台，或已经
获得任何商业组件许可。

## 影响与代价

- 保持 [ADR-0001](0001-single-core-and-thin-shells.md) 定义的纯核心边界，
  新适配能力通过显式模型转换与核心交互。
- 必须处理宿主实体引用稳定性、单位、局部坐标、约束方向、版本差异和
  受支持子集；这些都是需要测试的新工作。
- 独立几何检查仍是正确性依据之一，宿主返回“成功”不能替代它。
- 目前没有 Onshape 适配 crate、导入导出保证或远程调用交付物。

## 实施与验收证据

目前的证据是已存在的 PDR-1，而非集成测试。实施工作进入
[roadmap 的行业验证与集成阶段](../roadmap.md) 后，应补充：

- 实际使用的 API/模型语义版本、核验日期和支持映射表。
- 装配导入、求解、诊断映射及必要导出的完整回放样例。
- 单位与局部坐标变换、方向/分支、有损或不支持约束的测试。
- 与宿主和独立裁判交叉验证的几何结果，以及适配失败的明确错误。

## 重新评估条件

若所需接口不可用、真实用户的首要平台改变，或验证出的语义/运维成本
不适合首个交付场景，应补写新的产品方向决策，并关联替代本 ADR 的记录。
不得直接把优先候选写成已完成能力。
