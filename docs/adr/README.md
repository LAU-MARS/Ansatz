# 架构决策记录（ADR）

ADR 记录影响接口、数值行为或长期演进的重要选择，解释为何采用当前方案，以及何时需要重新评估。实现状态见 [架构](../architecture.md)，待办与验收条件见 [演进路线](../roadmap.md)。

## 记录约定

- 0001—0007 于 **2026-10-13** 根据当前代码补写，状态为「已采纳，回溯记录」。记录日期不代表原始决策发生日期。
- 「已采纳」表示当前实现采用该选择；具体覆盖范围与限制以各记录的决策、证据和代码为准。
- 0008 记录未来集成的已采纳方向，来源为 `AGENTS.md` 的历史 PDR；它不表示集成已经实现。
- 实验方案、候选指标与未来工作写入路线图；需要改变架构选择时先提出 ADR，避免把计划描述成现状。
- 改变已采纳决策时，新建后续 ADR，并把旧记录标为「已替代」，链接替代记录。历史理由保留。
- 每份记录应提供源码、契约或测试的相对链接；精确常量与能力边界应随实现变更复查。

## 新增记录

复制 [模板](template.md)，使用下一个编号和稳定的英文文件名。至少说明问题、采用方案、替代方案、代价、当前实现证据和重新评估条件，再更新本索引。

记录应使读者能区分：已经实现的能力、对外承诺，以及仍需验证的假设。测试通过是具体证据，不应被扩展为任意输入都可靠的证明。
